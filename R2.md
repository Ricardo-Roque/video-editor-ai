# R2: onde fica a mídia dos criativos

Imagens, takes, vídeos finais, referências e os textos de cada criativo ficam num bucket **privado** do Cloudflare R2. O índice (o que existe, de qual criativo, tamanho, duração, linha do tempo dos takes) fica na tabela `arquivos` do Supabase. Com isso:

- O painel mostra tudo em qualquer computador. Quando o arquivo não está na máquina, o vídeo toca direto do R2 por um link temporário (6 h).
- `painel.py entregar` sobe sozinho o que é novo ou mudou na etapa entregue.
- Para continuar um criativo feito em outro computador: `python -I -X utf8 tools/midia.py baixar C13`.

**Custo**: 10 GB grátis por mês e depois US$ 0,015 por GB por mês. Assistir e baixar não custa nada, porque o R2 não cobra saída de dados. A meta é ficar dentro dos 10 GB:

- Os intermediários da montagem (`seg_NN.mp4`, `assembled.mp4`) não sobem, porque saem de novo dos takes.
- **Takes e imagens sobem compactados**. O take vai em H.264 CRF 26 na mesma resolução, com uns 26% do tamanho e sem diferença visível. A imagem vai em WebP 90, com uns 17% do tamanho e mantendo a transparência. O original continua no computador de quem gerou. O `baixar` devolve a imagem no formato do nome (`.png`/`.jpg`).
- O vídeo final, as referências e os textos sobem intactos.
- `verificar`, `estado` e `subir` mostram quanto dos 10 GB está em uso. A partir de 80% aparece um aviso.

Em 2026-11-26 o acervo tinha 2,1 GB sem compactar. Metade é vídeo final (uns 45 MB cada); um criativo em vídeo novo ocupa uns 50 MB.

Uma conta, um bucket e um token servem o time todo. Quem cria a conta faz os passos 1 a 3 uma vez e passa as linhas `R2_*` do `.env` para o sócio por um canal privado. Nunca no chat, no Git ou no painel.

## 1. Conta e R2 (5 min)

1. Crie a conta em [dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up), ou entre se já tiver uma.
2. No menu da esquerda: **R2 Object Storage**. Na primeira vez, a Cloudflare pede um cartão para ativar o R2. Nada é cobrado enquanto o uso ficar dentro do plano grátis.

## 2. Bucket

1. **R2 > Create bucket**. Nome: `criativos`. Localização: **Automatic**. Classe: **Standard**. A classe Infrequent Access não tem plano grátis.
2. Deixe o bucket **privado**: não ligue "Public access" nem o domínio `r2.dev`. O painel usa links assinados.

## 3. Token da API

1. **R2 > Manage API tokens** (ou "API" no canto direito da página do R2) **> Create API token**.
2. Nome: `painel-criativos`. Permissão: **Object Read & Write**. Escopo: **Apply to specific buckets only**, marque `criativos`. Validade: sem prazo (ou o prazo que preferir).
3. A Cloudflare mostra o **Access Key ID** e o **Secret Access Key** uma única vez. Copie os dois **direto para o `.env`**.
4. O **Account ID** aparece na página inicial do R2 (lado direito) e na URL do painel da Cloudflare.

## 4. `.env`

```
R2_ACCOUNT_ID=...            # Account ID da Cloudflare
R2_ACCESS_KEY_ID=...         # Access Key ID do token
R2_SECRET_ACCESS_KEY=...     # Secret Access Key do token
R2_BUCKET=criativos          # opcional, este é o padrão
```

Instale a dependência nova (`pip install -r requirements.txt`) e confira:

```
python -I -X utf8 tools/midia.py verificar
```

## 5. Primeiro envio (uma vez só)

```
python -I -X utf8 tools/midia.py subir --todos --ensaio    # mostra o que vai subir, sem enviar
python -I -X utf8 tools/midia.py subir --todos             # envia (2 GB: de minutos a uma hora, conforme a internet)
```

Pode rodar de novo quantas vezes quiser: o que já está no R2 com o mesmo conteúdo é pulado.

## Uso diário

| Comando | Para quê |
|---|---|
| `midia.py subir C13 [CN05 ...]` | envia o que é novo ou mudou (o `entregar` já faz isso) |
| `midia.py baixar C13 [--papel take]` | traz para o computador o que só está no R2. Nunca sobrescreve arquivo local |
| `midia.py estado [C13]` | o que está no R2, por criativo e tipo |
| `midia.py verificar` | credenciais, bucket e total guardado |

Regras:

- Um arquivo apagado no computador **não** é apagado do R2. Take refeito (`T03_v2`) sobe ao lado do antigo.
- Quando a pasta do criativo muda de lugar ao ser entregue (para `Criativos Exemplo/<formato>/`), o próximo `subir` só atualiza o índice, sem reenviar nada.
- Na renumeração de criativos, a migração precisa atualizar também `arquivos.criativo_id`. As chaves no bucket não mudam.
