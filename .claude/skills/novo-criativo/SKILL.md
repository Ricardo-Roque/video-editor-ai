Use when the user says "novo criativo", "criativo nativo", "modelar" or "modelagem", names a "Criativo NN", drops a new reference video in "Vídeo Bruto/", sends a facebook.com/ads/library link, or asks to continue a creative's next stage.

# Novo criativo

1. Read `PROCESSO.md`, `CLAUDE.md` and `PRODUTOS.md` at the project root. They are the source of truth for every step, tool command, naming convention, product fact and rule.
   - **Pick the process first.** Réplica: redo the reference as faithfully as possible in another language and country (`PROCESSO.md`, Etapas 0 to 6). Modelagem: break the reference down into variables, read the brand's library in `Variáveis/<Marca>.md`, propose concept tests that stack proven winners and change one variable, then write a new script on the same skeleton (`MODELAGEM.md`, M0 to M6; production is still PROCESSO.md Etapas 3 to 6 or N3 to N4). "Traduzir", "refazer", "replicar" means Réplica; "modelar", "criar a partir de", "conceito novo", "variação de um vencedor" means Modelagem; if unclear, ask. Most native creatives so far were Modelagem (the old Etapa 2b).
   - Both processes read the brand library before analysing and add the reference's variables to it. Swipe variables are always Candidate; only performance numbers against the control make a Winner or Loser.
2. `Criativos Exemplo/` has one folder per format (all 16 from the team's Trello board), each with a `FORMATO.md` guide (why it holds attention, how to write the script, how to produce it here, cost, risks) plus the delivered creatives in that format. Formats are the 16 from the team's Trello board, summarised in `FORMATOS.md` together with script structures and attention elements. Work out which format and script structure the reference follows; read that format's `FORMATO.md` and flag any missing tool it mentions before spending; in the analysis, annotate every line of the reference with the attention elements from `FORMATOS.md` (the map the translation must preserve); for a new script built from a winning creative, follow Modelagem in `MODELAGEM.md` (the old Etapa 2b); and use the example folders (analise, prompts, takes_config, montagem.json, production notes) as the template. `CRIATIVOS.md` is the catalog with costs and lessons.
3. Identify the creative:
   - From the panel's Garimpo: a card in the Fila created by an approved request already has its code, offer, process (Réplica or Modelagem), priority and the owner's request; `painel.py esteira` prints them with the reference link or file. Create the folder with that code, follow the process the request names, and ask only if the offer is missing.
   - New: ask only for what is missing among: creative type and number (one gap-free sequence per type: folder `Criativo NN` for video, `Criativo Nativo NN`, `Criativo de Imagem NN`; codes `CNN`, `CNNN`, `CINN`; get the next free one with `python -I -X utf8 tools/painel.py proximo --tipo video|nativo|imagem`, never the reference file's number), reference file in `Vídeo Bruto/`, target language, target country, product (and whether packaging or claims change), and whether the format follows the reference or another one. Then do Etapa 0 (copy `_Modelo Criativo/` into `Criativo NN/` at the project root, where creatives stay while in production; check that the video model is up).
   - Existing: open the creative's folder (`Criativo NN/`, `Criativo Nativo NN/` or `Criativo de Imagem NN/`) (at the root if in production, in `Criativos Exemplo/<format>/` if delivered) and work out the process and current stage from the files present (Réplica: analise.md; Modelagem: quebra.md, conceito.md; then roteiro, imagens, takes, montagem) and the "Notas de produção" in the roteiro. Tell the user where it stands and what comes next. If images or takes are missing because media is not in Git, ask the user to copy them from the team's shared folder.
   - Native: if the reference is a static ad (one photo, a long post text and a link, usually a `facebook.com/ads/library` link), follow "Criativo nativo" in `PROCESSO.md` and `Criativos Exemplo/Nativo/FORMATO.md`. There are no takes and no montage, and no reference file is needed in `Vídeo Bruto/`. At delivery, always hand the user the approved image (its path) and the post description: write `copy_final_<language>.txt` with the link title, link description, button and post text without the ⚠ marks, and show it in the chat in a code block ready to copy. Also give the link title's back-translation and list the lines still waiting on confirmation. Video creatives keep the normal process.
4. Run the next stage exactly as PROCESSO.md describes, then stop at its approval gate. Approval happens in the panel ("Esteira de produção" in PROCESSO.md): a new creative enters with `tools/painel.py entrar C<NN>`; when a stage is done, update the creative's `ficha.json` (script split into hook, body and CTA, ad text with primary text, headline, description and button, Portuguese back-translation of every foreign line) and run `tools/painel.py entregar C<NN> --etapa <stage> --custo <US$>`; then tell the user in Portuguese, in a few lines, that the card is waiting for approval in the panel (costs estimated before and spent after). "Continue a esteira" means: run `tools/painel.py esteira` and work the cards that are with Claude, quoting cost before any paid generation.
5. When the creative is delivered, follow "Ao entregar um criativo" in `PROCESSO.md`: production notes; move the folder into `Criativos Exemplo/<format>/` and change the `../` output and font paths in its `montagem*.json` to `../../../` (first creative of a format: add its examples table and lessons to that `FORMATO.md`); update `CRIATIVOS.md` and the `FORMATO.md`; record new product facts in `PRODUTOS.md`; make sure the creative's variables are in `Variáveis/<Marca>.md` and, for Modelagem, set its test to "entregue" and give the ad name `C<NN> | <test ID> | <variable>: <value>`; document new tools in `PROCESSO.md`; then offer to commit and push.
